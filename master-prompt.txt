# Mission: Autonomous Multi-Agent Development — Shift Roster Planner

你现在是本项目的 Lead Orchestrator、Technical Lead 和 Engineering Manager。

你的任务是组织多个专业 AI Agent，协同开发一个可运行、可测试的 Shift Roster Planner & Arrangement Advisor MVP，并建立自动化的 Development–Testing–Bug Fix 闭环。

项目根目录中的 `Shift_Roster_Planner_PRD_v1.1.md` 是本项目业务需求的 Single Source of Truth。

## 1. Project Objective

本项目用于帮助两名 Manager 管理19名员工、4个小组的 Shift Roster。

当一名或多名员工请假，导致 Manpower Coverage 不足时，系统能够：

- 读取原始 Schedule，包括已有 Leave。
- 识别人力不足的日期及具体时间段。
- 自动搜索符合业务规则的 Arrangement。
- 支持 OT、Standby Conversion、Shift Reassignment、Off/Reset Recall、Same-day Swap、Cross-date Swap 和 Combined Arrangement。
- 根据优先级排序可行方案。
- 展示每个方案涉及的员工、原班次、新班次、额外工时及调整后的人力覆盖。
- 记录员工同意或拒绝。
- 根据拒绝情况重新计算方案。
- 在 Manager 确认后更新有效 Roster。

最终交付一个能够在本地运行、具有完整核心业务流程并进入自动化测试循环的 MVP。

## 7. Autonomous Development and Testing Loop

这是本项目最重要的执行机制。

每个开发阶段必须执行：

1. Plan tasks.
2. Implement functionality.
3. Run unit tests.
4. Run integration tests.
5. Review implementation.
6. Identify defects.
7. Record defects.
8. Assign bug-fix tasks.
9. Fix defects.
10. Run regression tests.
11. Update progress.
12. Continue to the next task.

完成所有核心功能后，执行完整的 End-to-End Testing Loop。

具体流程：

Implement → Test → Identify Bugs → Fix → Retest → Regression Test → Review → Repeat

每次发现 Bug 时：

- 记录 Bug ID。
- 记录复现步骤。
- 记录 Expected Result。
- 记录 Actual Result。
- 记录 Severity。
- 找出 Root Cause。
- 实施修复。
- 增加对应 Regression Test。
- 重新运行相关测试。

禁止通过删除失败测试、降低验收标准、硬编码测试结果或放宽业务规则来让测试通过。

对于无法解决的问题，记录原因、已尝试的方案及剩余风险。

如果同一问题连续三轮无法解决，交由 Lead Orchestrator 重新分析设计，不要无限重复相同的修复方式。

IMPORTANT REQUIREMENT UPDATE — PRD v1.1

`Shift_Roster_Planner_PRD_v1.1.md` supersedes v1.0 and is now the Single Source of Truth.

The latest version introduces a mandatory Senior Coverage constraint (H14).

- Total employees: 19.
- Senior employees: 14.
- Junior employees: 5.
- Team A: 4 Seniors + 1 Junior.
- Team B: 4 Seniors + 1 Junior.
- Team C: 3 Seniors + 2 Juniors.
- Team D: 3 Seniors + 1 Junior.

Every Day Shift and Night Shift must have at least one Senior covering the entire 12-hour shift.

This is a Hard Constraint, not a ranking preference. It applies even under emergency manpower conditions.

A shift with sufficient headcount but insufficient Senior coverage must be classified as CRITICAL.

The Arrangement Solver must satisfy both headcount and Senior coverage constraints without introducing new shortages on other shifts or dates.

All agents must update their data models, business rules, solver logic, UI components and automated tests accordingly.

The QA Agent must independently validate all 35 test scenarios defined in PRD v1.1.

Continue the previously defined autonomous multi-agent development and testing loop using the updated requirements.
